# O_DOCK 중복 이미지 정리

같은 상품의 같은 버전(variant) 안에서 비교합니다. 다른 상품·색상·재판 버전 사이의 이미지는 합치지 않습니다. 기존 앱 소스를 덮어쓰거나 DB 스키마를 변경하지 않는 독립 실행 도구입니다.

## 정리 기준

| 종류 | 의미 | 처리 |
|---|---|---|
| exact_bytes | 파일 내용이 완전히 동일 | 기본 적용 대상 |
| exact_pixels | 파일 저장 방식은 다르지만 크기·보정된 RGBA 픽셀이 동일 | 기본 적용 대상 |
| similar | 같은 화면 구도이며 해상도·압축 정도가 다른 것으로 추정 | 비교 화면에서 확인 후 별도 선택 |

유사도는 화면 비율, 차이 해시, 축소 RGB 차이와 부분 영역 차이를 함께 사용합니다. 유사도 수치는 정답 확률이 아닙니다. 실제 사진에서 얼굴·색상·액세서리 차이가 없는지 확인하세요. 다른 각도·확대·크롭은 보존하는 방향으로 엄격하게 후보를 선정하지만 오탐을 완전히 보장할 수는 없습니다.

허용 범위가 같은 이미지 중 해상도가 높은 파일을 우선 유지합니다. authorized는 personal_local보다 우선합니다. 네트워크 이미지 다운로드·번역·유료 AI 호출은 하지 않습니다. 로컬 파일을 찾을 수 없거나 손상·애니메이션·너무 큰 파일이면 검사에서 건너뜁니다. 표시 가능한 두 상태의 이미지만 대상으로 합니다.

## 1. 폴더 배치 및 검사

압축을 풀고 `tools/image_dedup` 폴더를 프로젝트의 `tools/image_dedup` 경로에 보관합니다. 프로젝트 루트의 Git Bash에서:

```bash
bash tools/image_dedup/run.sh audit
```

필요하면 Pillow 이미지 분석 라이브러리를 실행 중인 백엔드 컨테이너의 임시 경로에 설치합니다. 이때만 패키지 다운로드가 필요할 수 있습니다. 이미지 수가 많으면 시간이 걸립니다. 수집 워커는 검사와 적용 중 변경을 막기 위해 중지하며 자동 재시작하지 않습니다.

처음 5개만 검사하려면 위 전체 검사 대신:

```bash
bash tools/image_dedup/run.sh audit --figure-ids 48,49,50,51,52
```

결과:

- `backups/migrations/image_dedup/audit.html`: 브라우저에서 여는 좌우 이미지 비교표. 이미지를 내장하여 외부 접속 없이 열립니다.
- `backups/migrations/image_dedup/audit.json`: 적용에 사용하는 계획의 로컬 사본.
- Docker media 볼륨 안 `/app/media/image_dedup_reports/audit.json`: 실제 적용 명령이 읽는 계획.

audit는 DB와 원본 이미지 파일을 수정하지 않습니다. 다시 검사하면 audit.json/html은 최신 결과로 바뀌므로 이전 검사를 보존하려면 이름을 바꿔 복사해 두세요.

## 2. 완전히 같은 이미지부터 정리

검사가 성공한 다음:

```bash
bash tools/image_dedup/run.sh apply
```

기본 적용은 exact_bytes/exact_pixels만 대상으로 합니다. 먼저 PostgreSQL 덤프를 생성하고 읽을 수 있는지 검사합니다. 계획의 DB 연결 및 이미지 해시가 현재와 같은지 재확인한 후 한 트랜잭션으로 변경합니다. 변경이 발견되면 적용하지 않고 재검사를 요구합니다.

**이번 도구의 삭제는 갤러리에서 제외하는 방식입니다.** 중복 행의 usage_status를 duplicate_hidden으로 바꾸며 실제 원본 파일과 DB 행은 보존합니다. 따라서 공용 이미지 참조가 깨지지 않고 되돌릴 수 있습니다. 디스크 공간은 줄지 않습니다. 실제 파일 영구 삭제와 재수집 시 중복 방지 기능은 이 도구에 포함되지 않습니다.

브라우저를 새로고침하면 중복 사진이 갤러리에서 빠집니다. 적용 이력과 DB 덤프는 `backups/migrations/image_dedup`에, 복구 이력은 media 볼륨에도 남습니다.

## 3. 비슷한 사진은 확인한 ID만 선택

HTML의 `제외 ID`를 확인하고, 정말 동일한 사진인 행만 골라 적용할 수 있습니다. 아래 123,456은 예시이므로 실제 ID로 바꾸세요.

```bash
bash tools/image_dedup/run.sh apply --include-similar --image-ids 123,456
```

같은 감사 계획에서 이미 exact 항목을 정리했다면 전체 audit를 다시 실행한 뒤 선택하세요. 비교표의 similar 후보 전체를 확인한 경우에만 `--image-ids`를 생략해 모두 적용할 수 있습니다.

## 복구

적용 출력 마지막 줄에 해당 실행의 복구 명령이 표시됩니다. 예:

```bash
bash tools/image_dedup/run.sh restore --report /app/media/image_dedup_reports/apply_날짜_시간_번호.json
```

원본 상태를 복원하며 파일을 삭제하지 않습니다. 이후 이미지 연결이나 상태가 변경됐다면 덮어쓰지 않고 중단합니다. 복구 명령은 같은 이력에 반복 실행할 수 있습니다.

## 검증 범위

격리 SQLite와 합성 이미지로 동일 파일·동일 픽셀·크기 차이·다른 각도 및 크롭·다른 버전 보존·공용 파일 참조·원본 변경 차단·숨김 후 기존 갤러리 제외·복구를 검사했습니다. 사용자 실제 이미지·Docker·PostgreSQL에 접속해 중복 개수를 확인하거나 정리를 실행한 결과는 아닙니다. 실제 사진의 유사도 정확도는 audit.html로 확인해야 합니다.
