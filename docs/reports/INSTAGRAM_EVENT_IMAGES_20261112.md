파일을 브라우저로 열면 각 게시물의 이미지가 갤러리로 표시되고 클릭해 원본 크기로 볼 수 있다. 같은 폴더의 `media/`에 파일, `posts.json`에 게시물·이미지 ID·원문 출처·파일 hash·수집 시각·상태가 있다. HTML의 `<img>` 93개와 실제 파일 참조가 전부 일치함을 확인했고 실제 이미지 1장도 열어 확인했다. 브라우저 UI 자동 검증은 수행하지 않았다.

기존 원문·후보 판단·공개 상태를 바꾸지 않고 별도 파일로 보강했다. PostgreSQL 추가 변경은 없으며 이미지 metadata는 비공개 JSON에 보관한다. 행사 후보 수는 이전과 같이 18개 게시물이고 동일 행사 공지를 포함한다. 이미지 안의 글씨를 OCR로 추출하거나 그 내용으로 날짜·장소를 자동 확정하지 않았다.

## 구현

- `client.py`: 선택적인 `media_url`, `thumbnail_url`, `children.limit(20)` 이미지 필드.
- `images.py`: API 이미지/캐러셀 순서·영상 썸네일 선택, 공식 Meta CDN 제한, 공인 DNS 확인, 리디렉션/토큰 전송 차단, 타입·크기 검증, SHA256 파일 보관.
- `collect_instagram_images.py`: 현재 인증·타사 조회 게이트를 다시 통과한 뒤 기존 게시물과 ID로 매칭하여 내부 검수 목록 보강.
- `review.py`: 외부 이미지 로딩 대신 로컬 hash 경로만 표시, 클릭 원본 보기, 출처·원문 유지.
- `test_instagram_images.py`: URL 경계·사설 주소·캐러셀·영상 제외·비밀값 비전송·중복 파일·타입·크기·HTML 경로 검증.

이미지·행사·인증 관련 테스트 **63 passed**. 프로젝트 구조 검사 오류 0건. 공개 화면·기존 상품 번역·분류·RAG·자동 스케줄러는 변경하지 않았다. 기존 토큰의 최신 만료 정보는 이 실행 폴더의 `availability.json`에 별도로 기록했다.

이미지는 API가 접근을 허용해 반환한 파일을 내부 검수용으로 보관한 것이며, 사이트 공개나 재배포 권리를 별도로 확인했다고 주장하지 않는다. 파일은 Git 제외된 `data/private/`에 보관했고 크롤링·쿠키 접근·사설 API·다운로드 제한 우회를 하지 않았다. API가 이미지를 주지 않으면 원문 링크만 유지한다. 이미지 보존·삭제 동기화·공개 승인 흐름은 후속 운영 과제다.
