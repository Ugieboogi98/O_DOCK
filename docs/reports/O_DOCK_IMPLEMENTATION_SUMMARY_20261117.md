# O_DOCK 구현 현황 정리

작성일: 2026-11-17 · 기준 시간대: Asia/Seoul

현재 저장소의 코드, 기능별 작업 보고서, 수집 결과 및 처리 상태 파일을 기준으로 정리했다. 구현 여부와 데이터 처리 완료 여부는 구분한다. 과거 테스트 결과는 해당 변경 시점의 기록이며, 이 문서 작성 과정에서 전체 테스트나 수집을 다시 실행하지 않았다.

## 1. 서비스 개요

O_DOCK은 일본 공식 피규어·굿즈 정보를 수집해 한국어로 탐색하고, 국내 판매 가격을 비교하며, 관심상품과 구매 기록을 관리하는 서비스다. 서브컬처 팝업·전시회·콜라보 카페 등의 행사 정보도 별도 탭에서 제공한다.

| 구성 | 사용 기술·역할 |
|---|---|
| 프론트엔드 | Vue 3, Vue Router, Pinia, Vite, Tailwind CSS, Lucide |
| API 서버 | FastAPI, 상품·검색·계정·가격·행사 API |
| 데이터베이스 | PostgreSQL, 상품·원문·분류·가격·계정·개인 기록 저장 |
| 검색 인덱스 | Chroma 기반 검색 인덱스와 기존 검색·RAG 경로 |
| 로컬 모델 서버 | Ollama, 번역·분류 역할별 모델 실행 |
| 실행 환경 | Docker Compose 서비스 + 호스트에서 실행하는 작업 도구 |

## 2. 서비스 운영 흐름

### 서버의 상품 처리

공식 제조사·국내 유통사 수집 → 원문·이미지 및 출처 보존 → 중복 확인 → 사전 조회 → 상품명 번역 → 작품·캐릭터·형태 등 분류 → 원문 근거 검증 → 유효 필드 저장·검색 인덱스 반영 → 사용자 화면 제공

수집된 원문과 상품 기본 정보는 먼저 저장할 수 있다. 번역·분류는 대기열에서 별도로 처리하고 검증한 결과를 갱신한다. 따라서 수집 완료가 번역·분류 완료를 뜻하지는 않는다.

### 서버의 행사 처리

공식 홈페이지·사용 가능한 Instagram API 조회 → 행사 여부·유형·일정·장소 추출 → 최초 수집 전에 종료된 행사 제외 → 동일 행사 공지 통합 → DB 저장 → 행사 탭에 직접 표시 → 조회 날짜에 따라 예정·진행·종료 상태 계산

행사 관리자 검수함은 만들지 않았다. 추출·게시 조건을 통과한 행사 정보를 바로 제공한다.

### 사용자 이용

상품·신상품 둘러보기 → 제조사·작품별 탐색 또는 캐릭터·한국어 검색 → 상품 상세와 공식 출처 확인 → 국내 4개 유통사 가격 비교 → 로그인 후 관심상품 등록 및 구매·배송 기록 관리

행사 탭에서는 행사 종류·일정 등을 확인하고 상세 정보와 원문·예약 링크로 이동할 수 있다.

### 관리자 이용

데이터 현황 화면에서 관리자 토큰으로 연결 → 카탈로그 상태 확인 → 제한된 최신 상품 갱신 요청 → 수집·번역·분류 상태 및 보고서 확인

일반 사용자 계정과 공용 카탈로그 관리자 권한을 분리했다. 일반 방문만으로 수집이 시작되지는 않는다. 별도의 종합 사용자 관리 콘솔은 현재 완료 기능으로 포함하지 않는다.

## 3. 사용자 기능

| 영역 | 구현 내용 |
|---|---|
| 상품 탐색 | 전체 상품, 신상품, 제조사별·작품별 목록, 필터·정렬·페이지 이동 |
| 검색 | 한국어 검색, 작품·캐릭터 등 분류 정보 활용, 기존 검색·AI 채팅 화면 |
| 상품 상세 | 큰 대표 사진, 썸네일, 상세 이미지 갤러리, 제조사·작품·캐릭터·크기·발매 정보 |
| 가격 | 공식 엔화 가격, 환율 환산 참고 가격, 국내 유통사별 가격과 최저가 |
| 출처 | 공식 상품 페이지 및 국내 판매 페이지 연결 |
| 계정 | 회원가입, 로그인·로그아웃, 세션과 비밀번호 해시 처리 |
| 개인 기록 | 사용자별 관심상품, 구매·배송 기록 관리 및 소유권 검사 |
| 상품 비교 | 비교 패널과 비교 화면, 키보드 닫기·포커스 처리 |
| 행사 | 행사 목록·필터·상세, 일정 상태, 이미지가 있는 출처의 이미지 표시 |
| 운영 현황 | 데이터 현황 및 관리자 연결 화면 |

데이터에 없는 가격·이미지·번역·분류는 미확인 상태로 남긴다. 화면 존재만으로 모든 상품의 데이터가 채워진 것은 아니다.

## 4. 공식 제조사 상품 수집

### 공통 처리

- 허용된 출처에서 상품명·설명·제조사·발매일·가격·이미지·상품 URL 등을 수집한다.
- URL, JAN, 상품 식별자와 기존 레코드를 확인해 중복 삽입을 줄인다.
- 수집 결과를 의미 검증 대기열과 연결하고, 체크포인트 및 회차별 보고서를 남긴다.
- 허용 호스트·robots.txt·요청 간격·응답 크기·재시도 상한을 적용한다.
- 접근 거절이나 인증 제한을 우회하지 않고 실패·누락 사유를 기록한다.

### 최근 수집 결과

굿스마일 요청 회차에서는 신규 상품 500건을 확보하고 이미지·JAN·엔화 가격 및 상세 API를 확인했다. 이후 11월 17일 제조사 수집에서는 굿스마일을 제외하고 다음 151건을 추가했다.

| 제조사 | 11월 17일 신규 상품 |
|---|---:|
| 타이토 | 25 |
| 반다이 | 48 |
| 세가 | 56 |
| 후류 | 2 |
| 핫토이 | 20 |
| 메가하우스 | 0 |
| 합계 | 151 |

이 회차에서 전체 상품은 6,722건에서 6,873건으로 늘었다. 신규 151건의 상세 API·검색 색인을 확인했고 이미지 357개를 저장했다. 일부 반다이 경품 상품은 이미지 서버의 접근 거절로 이미지가 누락됐다.

**핫토이 20건은 제외 지시 이전의 수집 기록이다. 현재는 공식·수동·유통사 수집 경로에서 핫토이를 제외하며 기존 상품은 보존한다.** 굿스마일 제외는 위 신규 제조사 수집 회차의 범위이며 영구 수집 제외 정책과 구분한다.

코토부키야는 접근 거절, 후류 쇼핑몰은 요청 제한으로 일부 수집이 제한됐다. 세가는 이번에 확보한 공식 웹앱 후보 목록을 사용했으며 일반 HTML 수집만으로 향후 신규 목록 전체가 자동 발견되는 것은 아니다.

## 5. 국내 4개 유통사 가격

대상은 매니아하우스, 히어로타임, 피규어팜, 코믹스아트다.

- 상품 상세에 비교 대상 4개 유통사를 표시하고, 정보가 없으면 `가격 없음`으로 표시한다.
- 비교 가능한 최신 양수 원화 가격 중 최저가를 대표 가격으로 사용한다.
- 품절 가격, 예약금·잔금·조건부 가격 등을 최저가 선정에서 제외한다. 배송비를 합산한 최종 결제액 비교는 아니다.
- JAN이 유일하고 제조사·판본·스케일 등이 충돌하지 않는 경우만 자동 연결한다. 확신할 수 없는 관측은 미연결 상태로 보존한다.
- 제조사 수집 회차에 국내 4개 유통사 확인을 함께 실행하도록 연결했다. 기본 범위는 유통사별 상세 페이지 20개이며 매번 전 상품을 완주하는 방식은 아니다.
- 검토된 유통사 자료 가져오기 경로에서는 기존에 없던 상품을 ETC로 추가하고 실제 제조사 정보를 별도로 보존했다. 일반 가격 관측이 모두 새 상품으로 생성되는 것은 아니다.

11월 17일 회차 결과:

| 유통사 | 상품·가격 관측 |
|---|---:|
| 매니아하우스 | 20 |
| 히어로타임 | 18 |
| 피규어팜 | 20 |
| 코믹스아트 | 20 |
| 합계 | 78 |

78건 중 기존 상품에 연결된 관측은 9건, 미연결 관측은 69건이다. 히어로타임의 성인 인증 페이지 2개는 건너뛰었다. 관측 78건을 신규 피규어 78건으로 계산하면 안 된다.

## 6. 번역·분류 분리와 사전

### 처리 구조

기존 자료 조사 → 버전이 있는 참조 사전 생성 → 사전으로 해결 가능한 항목 재사용 → 번역 모델 → 분류 모델 → 원문 근거 검증 → 단계별 저장·실패 재시도

| 역할 | 현재 구성 |
|---|---|
| 상품명 번역 | `qwen3:8b` |
| 작품·캐릭터 등 분류 | `qwen3:1.7b` |
| 공통 실행 | 로컬 Ollama, 역할별 컨텍스트 4,096 |
| 처리기 | `split-semantics-v6`, 기본 20건 단위 |
| 검증 | 사전 문맥·원문 인용·필드 허용 규칙·원문 버전 확인 |

이는 모델 가중치를 재학습한 결과가 아니라, 사전·프롬프트·검증·복구·작업 구조를 개선한 것이다. 새 분리 파이프라인의 번역 범위는 **상품명**이며 설명문 전체 번역과 구분한다. 이 경로는 로컬 모델만 사용하며 유료 모델 자동 대체를 하지 않는다.

### 사전 구성

- 기본 작품 규칙 1,135행, 캐릭터 규칙 252행 및 기존 보조 별칭·문맥 규칙을 통합했다.
- 재사용 가능한 정확한 상품명 번역 4,655개를 확보했다.
- 같은 제목이어도 제조사·작품·제품 라인 문맥과 번역 충돌을 확인한다.
- 원문·검증 결과 해시와 출처를 확인하며, 단순히 한글 이름이 있다는 이유로 승인하지 않는다.
- 사전 버전과 지문을 보존하고 새 모델의 추측을 자동으로 승인 사전에 넣지 않는다.
- 위 수치는 규칙·번역 항목 수이며 모두 서로 다른 작품·캐릭터 수를 뜻하지 않는다.

### 품질·복구 개선

- 긴 원문에서 상품명 번역과 분류 근거를 분리해 입력 길이 초과를 줄였다.
- 작품 문맥을 확인한 캐릭터 별칭과 원문에 명시된 관계만 연결한다.
- 나루토 복수 캐릭터, 무직전생 에리스, 원신 나히다, 파이널판타지14 에메트셀크 등의 반복 실패 사례를 보완했다.
- 액션·데포르메 피규어 표현의 추출·검증 규칙 불일치를 수정했다.
- 조각 번역 복구와 자체 재검토를 추가하되, 일본어 잔존이나 근거 부족 결과는 보류한다.
- 기존 기록 527건을 재검사해 13건에서 유효한 분류 필드를 추가했다. 모두 전체 완료가 된 것은 아니다.

### 상태와 재시도

- 번역·분류 캐시를 별도로 저장한다. 원문·사전·모델·프롬프트·파이프라인 버전을 키에 포함한다.
- 먼저 번역 배치를 처리하고 분류 배치를 처리해 모델 교체 횟수를 줄인다.
- 개별 상품 실패는 다음 상품 진행을 막지 않는다.
- 동일 실패는 기본 1시간 뒤 재시도하며 사전·파이프라인 변경 시 재검사할 수 있다.
- 모델 서버가 끊기면 대기 후 재연결하고 저장한 단계 결과를 재사용한다.
- 확인 완료 `ready`, 일부 확인 `partial`, 검토 필요 `review`를 구분한다. 원문 근거가 없는 필드를 채워 완료 수치를 늘리지 않는다.

## 7. 행사·SNS 수집

팝업스토어·전시회·콜라보 카페와 페어·페스티벌·팬 이벤트를 다룬다.

- 게시물 ID로 원본을 갱신하고 작품·유형·기간·장소를 비교해 같은 행사 공지를 통합한다.
- `진격의 거인展`처럼 전시가 명시되면 일반 팝업 표현보다 전시회 분류를 우선한다.
- `11/19~12/2` 같은 본문 날짜와 복수 일정·장소를 처리한다.
- 최초 수집 전에 이미 끝난 행사는 신규 노출에서 제외한다. 수집 당시 유효했던 행사는 보존하고 한국 날짜 기준으로 종료 상태를 갱신한다.
- Instagram 이미지 수집·표시 경로를 마련했다. 공식 홈페이지는 이용 범위를 구분해 행사 사실과 원문·예약 링크 중심으로 제공하며 모든 홈페이지 포스터를 복제하지 않는다.
- DUEX, Space Galleria, 애니메이트 코리아, 애니플러스, 팝콘D플레이, AGF Korea 등 공식 출처 수집기를 추가했다.

11월 12일 공식 출처 확장 당시 행사 카드는 25개였다. 이는 현재 진행 중인 행사 수가 아닌 당시 결과다. G-STAR는 robots 차단으로 수집하지 않았고, X는 API 구성이 없어 비활성화했으며 Popga/Popply는 참고 링크로만 등록했다.

**최신 Instagram 재실행 기록인 11월 16일에는 Meta가 `API access blocked`로 거절해 신규 게시물·이미지 저장이 0건이었다.** 수집기 구현과 실제 현재 API 접근 가능 여부를 구분해야 한다. 기존 행사 데이터는 보존했다. 전체 행사 출처의 상시 자동 수집 스케줄러를 활성화한 상태로 보고하지 않는다.

## 10. 운영·재개 구조

웹·API·PostgreSQL·Chroma는 Docker Compose로 구성하고, 현재 분리 번역·분류 소비자는 호스트 Python에서 로컬 Ollama와 DB에 연결한다. Docker에 별도 소비자 정의도 있지만 호스트 소비자와 동시에 실행하지 않는다.

- 웹 주소: `http://localhost:8080`
- API 문서: `http://localhost:8000/docs`
- 로컬 모델 서버: CPU Ollama 컨테이너 `odock-ollama-cpu-20261117`
- 일반 상품 수집·유통사 워커를 모두 상시 실행 중인 것으로 간주하지 않는다.

Docker가 꺼지면 API·DB·모델 연결이 중단되어 처리가 대기하거나 재연결이 필요하다. 커밋된 DB 데이터와 디스크 체크포인트·캐시는 보존하며, 재시작 후 미완료 작업을 이어간다. 호스트 처리 프로세스가 종료되면 별도로 다시 실행해야 한다. 미커밋 중간 작업은 재처리될 수 있다.

```powershell
# 기존 데이터·볼륨을 유지하는 서비스 업데이트
powershell -ExecutionPolicy Bypass -File scripts/update.ps1

# 로컬 모델 서버 재시작
docker start odock-ollama-cpu-20261117

# 기존 소비자가 종료된 것을 확인한 뒤 번역·분류 재개
.\.venv\Scripts\python.exe -u tools/run_split_semantics.py --watch --skip-failed --limit 20 --report-dir data/private/semantics/split_queue_20261117
```

`docker compose down -v`는 보존 중인 볼륨 데이터를 삭제할 수 있으므로 일반 재시작에 사용하지 않는다. `.env`의 실제 비밀 값은 이 문서에 포함하지 않는다.

문서 작성 과정의 Docker 상태 조회는 현재 도구 권한으로 거절되어 컨테이너의 실시간 상태를 새로 확인하지 못했다. 위 배포·실행 설명은 직전 운영 보고와 상태 파일을 기준으로 한다.

## 12. 남은 작업

11월 17일 16:41 정책 변경: 사용자 요청으로 실패 기록이 있는 상품은 자동 재시도에서 제외했다. 대기 데이터와 실패 원인을 보존하며 `skipped_failures.json`으로 별도 기록한다. 실패 보류만 남으면 `paused_failed`로 표시하므로 전체 번역·분류 완료와 구분한다. 특정 상품 재검사는 `--ids`로 수행할 수 있다.

1. 번역 검증 탈락 및 partial·review 상품의 용어·문맥을 보완하고 재처리한다.
2. 사람이 검수한 독립 표본으로 상품명·작품·캐릭터·형태별 정확도를 측정한다.
3. 미연결 국내 유통사 관측을 안전하게 연결하고 가격 커버리지를 확대한다.
4. Meta 앱·계정의 API 접근 제한이 해소되면 Instagram 수집을 재검증한다.
5. 접근 제한된 제조사·이미지 및 세가 동적 목록의 후속 수집 경로를 보완한다.
6. 로그인 이후 개인 기록 쓰기, 운영 중 장애·재시작 등 실제 사용 시나리오 검증을 확장한다.
