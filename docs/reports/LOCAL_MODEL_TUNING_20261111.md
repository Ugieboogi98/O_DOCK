# 일본어 번역·분류 모델 실제 튜닝 및 검증 — 2026-11-11

2026-11-12 후속 수정·전체 DB 재검증 결과는 [번역·캐릭터 누락 수정 보고서](LOCAL_MODEL_REPAIR_20261112.md)를 참고한다. 아래 수치는 11월 11일 실험 기록이다.

현재 판정은 **자동 운영 기준 미달**이다. Qwen3 8B 가중치를 두 차례 학습하고 프롬프트·사전·검증기를 수정했다. 실험 모델 등록과 추론은 성공했지만, 독립적인 새 상품에서 캐릭터 누락과 낮은 번역 처리율이 확인됐다. 이 보고서는 신뢰 수준 달성이나 배포 완료를 주장하지 않는다. 잘못된 이름을 추가 학습하는 일을 피하려면 다음 학습 전에 검수된 정답 자료가 필요하다.

## 사전·프롬프트·검증기 수정

원시 모델 제안과 자동 적용 후보를 분리했다. 사전에 없는 인명·작품명은 그럴듯한 한글 출력만으로 승인하지 않는다. 자동 번역 후보는 원문의 모든 일본어 부분을 사전으로 구성할 수 있을 때만 남긴다. 미상은 검수 대상이며 ‘캐릭터 없음’ 같은 확정 음성 라벨이 아니다.

- ‘スケールフィギュア’ 속 ‘ルフィ’를 루피로 인식하던 가타카나 부분 문자열 오탐 차단. 공백 정규화 경로에도 같은 경계를 적용했다.
- 원피스 의상과 작품 원피스 구분, 관련 상품 광고의 작품·형태 근거 제외, 높이·날짜를 축척으로 읽는 오류 차단.
- 카가미네 린·렌과 아스카의 서로 다른 인물 표기를 공유 위키 문서 때문에 합치던 오류 분리.
- 미쿠 시리즈 및 영화 제목 속 이름을 실제 상품 캐릭터로 오인하는 경우 차단.
- 작품 범위가 명시된 인명 사전 보강, 고질라·소피의 아틀리에 루트를 특정 후속작으로 확대하지 않도록 수정.
- 의상·조립 키트·탈것과 브랜드의 피규어 형태를 구분하고 명시적인 축척을 넓은 완성품 분류보다 우선했다.
- 번역의 키릴 문자 혼입, 숫자·축척·제품 코드 및 로마 숫자 시즌 누락 검증. 위키 문서 구분자를 상품 제목에 덧붙이지 않도록 정리했다.

사전 보강에 사용한 기존 60건과 100건은 개발 자료다. 해당 100건에서 캐릭터 recall 92.1%, 제안된 분류의 관측 오탐 0건이 나왔지만 **튜닝에 사용한 자료의 점수**이므로 독립 검증으로 제시하지 않는다.

## 새 상품 100건 검증과 실패 판정

seed `20261113`으로 실제 일본어 상품 100건을 새로 추출했다. 기존 160건, 학습 세트와 동일 상품군·URL·긴 설명 중복을 제외했다. 제조사는 후류·메가하우스·타이토 각 25건, 세가 17건, 반다이 8건이다. 모든 평가는 DB 읽기 또는 동결 JSON 사용이며 DB 쓰기와 유료 API 호출은 없다.

라벨은 후보 출력을 읽기 전에 작성했다. 이후 동의어 4건과 원문 사양 누락·잘못된 형태 라벨 2건이 발견돼 **별도 adjudicated 파일**에 이유를 기록했다. 보정 전 라벨·점수도 그대로 보존했다. 보정 후 숫자를 순수한 사전 인증 정답으로 표현해서는 안 된다.

| 사전 결합 제안값 지표 | 최초 라벨 | 6건 명시 보정 후 |
|---|---:|---:|
| 작품 precision / 비어 있지 않은 값 | 94.4% | 98.9% |
| 작품 coverage | 90.8% | 90.8% |
| 캐릭터 precision | 98.2% | 98.2% |

이 표의 ‘precision’은 점수기의 비어 있지 않은 제안값 기준이다. 실제 DB에 게시한 비율이나 자동 승인 상태의 의미 정확도와 동일하지 않다. 최초 라벨 기준 번역 `ready` 후보는 30/100건이었고, 수동 검토 중 로마 숫자 시즌 누락도 발견했다. **번역 의미 정확도는 인증하지 않았다.**

## 모델 산출물과 실행 안전성

실험 태그는 `odock-qwen3:8b-v2-experimental`이다. 현재 설치된 Ollama는 직접 ADAPTER import를 거절하여 전체 모델 병합 → BF16 GGUF → Q4_K_M 변환 후 등록했다. 원본 `qwen3:8b` 태그와 앱 기본 공급자는 유지했다. 새 코드는 격리 평가 컨테이너에서 검증했으며 운영 이미지는 재배포하지 않았다. DB 일괄 재분류와 자동 worker 활성화도 하지 않았다.

GGUF SHA256: `82087e7a304405d9cab26bff770b87e4de1ffb56746edcad8618426ad110245d`, 크기 약 5.02GB. llama.cpp revision은 `aa75ff3239f9cc675b081697deda9e1b112345c6`이다. 중간 병합·변환 산출물은 Docker volume `odock_tuning_20261111_v2`, Ollama 캐시는 기존 model_cache에 있다. 디스크에 큰 중간 산출물이 남아 있으며 자동 삭제하지 않았다.

초기 전체 CPU 병합 시 WSL VM 15GiB를 확인하지 않아 Docker 엔진이 응답하지 않는 문제가 있었다. Docker Desktop을 재시작하고 기존 DB·Chroma·백엔드·프런트엔드·Ollama 컨테이너를 데이터 삭제 없이 복구했다. 이후에는 샤드 단위 병합 10g, 변환 8g, 양자화 4g 메모리 제한으로 순차 실행했다. 전체 병합 스크립트에는 최소 32GiB 확인 장치를 추가했다. 샤드 병합 수학은 소형 BF16 모델에서 공식 PEFT merge와 텐서 단위 동일성을 확인했다.

회귀 테스트는 영화 제목·미쿠 시리즈·가타카나 경계·아스카 구분·높이/날짜·관련 광고·부정 표현·의상·탈것·로마 숫자 누락을 포함한다. 전체 백엔드 테스트는 **198 passed, 18 skipped**, 프로젝트 구조 검사 오류 0건이다. 샤드 병합 동등성 테스트도 1건 통과했다. 마지막 코드의 작품명 표시 정리는 동결 source 재검사로 확인했다. 기존 backend health HTTP 200, PostgreSQL·backend healthy와 frontend·Chroma·Ollama 실행 상태도 확인했다.

최신 v5b 개발 재검사에서는 작품 89/89, 캐릭터 55/55, 형태 73/73개의 비어 있지 않은 제안값이 라벨과 일치했다. 그러나 캐릭터 정답 90개 중 35개를 놓쳤고 번역 ready 후보는 **29/100건**이다. 이 값은 수정에 이미 사용한 표본의 결과이므로 독립 정확도 보증으로 사용하지 않는다. 충분한 사람 검수 gold와 별도 상품 검증 없이 자동 운영을 허용할 근거가 없다.
