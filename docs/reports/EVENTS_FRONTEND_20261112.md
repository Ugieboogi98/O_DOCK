# 행사 탐색 탭 구현·반영

## 사용자 요청에 따른 직접 표시로 변경

2026-11-12 후속 요청 ‘관리자 검수함 없이 바로 보여줘’에 따라 행사 목록·이미지를 인증 없이 표시하도록 변경했다. `/api/events`는 수집된 서브컬처 행사 게시물을 중복 묶은 11개 카드를 반환하고, `/api/events/images/{post_id}/{index}`는 해당 행사 이미지 사본만 제공한다. 비관련/행사 아님으로 제외된 게시물·이미지는 제공하지 않는다. 기존 관리자 검수함 UI와 행사 관리자 API를 제거했다.

화면에는 수집 정보와 공식 원문 링크를 표시하며 기계 추출 값을 검수 완료라고 표시하지 않는다. 기존 DB의 후보 상태를 강제로 APPROVED로 쓰지 않고 읽기 표시 경로만 변경했다. 아래의 관리자 전용 설명은 최초 구현 이력으로 현재 동작이 아니다. 변경 후 행사 API 테스트 8개, 프런트엔드 35개가 통과했다.

2026-11-12. 사용자가 제공한 팝가의 행사 탐색 페이지를 참고해 O_DOCK 화이트·블루 테마에 맞는 행사 목록을 구현했다. 참고 페이지의 필터·기간·정렬·탐색 흐름을 확인했으며 다른 사이트의 코드·이미지·행사 데이터를 복제하지 않았다.

## 이용 방법

- 상단 **행사** 탭: `http://localhost:8080/events`
- 행사 유형: 전체 / 팝업스토어 / 전시회 / 콜라보 카페
- 일정: 전체 / 진행 중 / 오픈 예정 / 종료 / 일정 확인 중
- 장소: 실제 원문에서 추출된 장소별 선택. 행정동 지오코딩·지도는 아직 구현하지 않았다.
- 행사·작품명 검색, 최근 공지순·오픈일순·종료일순, 12개 단위 페이지 이동.
- 카드 클릭: 이미지, 작품·기간·장소, 공식 원문·여러 공지를 상세 모달로 조회.

현재 공개 승인된 행사는 0개다. 일반 방문자에게는 공개 준비 안내가 보인다. **관리자 검수함**에서 기존 `ADMIN_TOKEN`으로 연결하거나, 이미 연결된 경우 **수집 후보 보기**를 선택하면 비공개 후보가 표시된다. 현재 게시물 18건이 가능한 중복 그룹을 묶어 카드 11개로 조회되며 장소 선택지는 6개다. 이 수는 확정 행사 수가 아니다. 출처·기간·장소가 충분히 일치한 공지만 묶고, 불충분한 공지는 별도로 남긴다.

수집 이미지와 원문은 관리자에게만 제공한다. 일반 로그인과 관리자 연결은 별개이며 기존 관리자 세션 방식을 재사용한다. 관리자 연결을 해제하면 후보·상세·메모리 이미지가 제거되고 공개 목록으로 전환한다. API 토큰을 URL·이미지 링크에 넣지 않으며, 보호된 이미지는 관리자 헤더를 붙여 받은 Blob으로만 표시한다. 공개 행사 API는 승인된 `events`만 읽고 원문 caption·비공개 이미지 경로는 반환하지 않는다.

이번 작업에는 승인·공개 버튼이 없다. 실제 관리자 검수·이미지 공개 권한 확인이 끝나기 전에 임의로 수집 후보를 공개 행사로 승격하지 않았다. 날짜는 Asia/Seoul 기준으로 계산하며 시작·종료일 중 하나라도 불명확하면 ‘일정 확인 중’으로 표시한다. 원문 이미지의 행사 일정을 OCR로 추론하지 않았다.

## 변경 파일

- `frontend/src/views/EventsView.vue`: 행사 목록·필터·검색·정렬·페이지·관리자 연결·상세 모달.
- `frontend/src/components/EventPoster.vue`: 인증 헤더 기반 이미지 수신·임시 Blob URL 생성/해제.
- `frontend/src/events.css`, `main.js`: 화이트·블루 화면·모바일 배치.
- `frontend/src/App.vue`, `router/index.js`: 행사 탭·라우트.
- `backend/app/services/event_catalog.py`: 공개/후보 읽기 분리·중복 묶기·이미지 매핑·필터·날짜 상태.
- `backend/app/api/events.py`, `main.py`: 공개 행사 및 관리자 전용 후보/이미지 GET API.
- `backend/tests/test_event_catalog.py`: 권한·공개 데이터 경계·이미지·필터·기간 테스트.

DB 데이터 변경이나 새 migration은 없었다. 기존 수집·번역 스냅샷과 작업 컨테이너는 수정·재실행하지 않았다. 다만 새 API를 제공하기 위해 현재 소스를 사용한 backend 이미지를 재빌드·교체했으며 프런트엔드도 교체했다. 자동 수집은 시작하지 않았다.

## 검증과 배포

- 프런트엔드 production build 성공, 기존 테스트 **35 passed**.
- 백엔드 전체 테스트 **272 passed, 18 skipped**.
- 이후 중복 그룹 이미지 전체 연결과 날짜 역전 방어를 보완하고 행사 API 전용 **8 passed** 재확인.
- 프로젝트 구조 검사 오류 0건.
- 실제 서버 `/api/events` HTTP 200 / 공개 행사 0.
- 미인증 `/api/admin/event-candidates` HTTP 403.
- 관리자 후보 HTTP 200 / 카드 11개 / 장소 6개.
- 관리자 이미지 HTTP 200 / `image/jpeg`, 미인증 이미지 HTTP 403.
- `http://localhost:8080/events` 및 backend health HTTP 200, Nginx를 통한 행사 API도 확인.

`docker compose build backend frontend` 후 `docker compose up -d --no-deps backend frontend`로 반영했다. 마지막 이미지 묶기 보완도 backend만 재빌드해 반영했다. 브라우저 UI 자동화가 이전 작업에서 사용할 수 없어 이번에는 production build·단위 테스트·실제 HTTP/API 응답으로 검증했다. 실제 브라우저 렌더링·모바일 터치 조작을 직접 완료했다고 주장하지 않는다.
