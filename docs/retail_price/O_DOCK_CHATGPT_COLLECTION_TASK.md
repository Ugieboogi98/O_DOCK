## 실행 방식

1. ChatGPT가 웹 검색·브라우저 도구를 사용해 목록과 상세 페이지를 직접 열고 상품별 정보를 판단한다. 검색 결과 요약만으로 가격을 확정하지 않는다.
2. 이번 수집 실행은 ChatGPT의 페이지 확인을 중심으로 진행한다. Docker worker 또는 로컬 Python 크롤러에 전체 수집을 맡기는 방식으로 대체하지 않는다.
3. 기존 자동 수집 프로세스의 실행 여부를 확인한다. 같은 판매처를 수집하는 프로세스가 남아 있으면 해당 수집 프로세스를 중지하고 진행 기록을 보존한다. DB는 기존 서비스를 이용할 수 있다.
4. 페이지를 읽어 검증한 결과의 JSON 저장, 중복 대조, DB 반영에는 로컬 코드와 기존 서비스를 활용할 수 있다. DB 저장 코드만 실행하고 ChatGPT가 직접 페이지를 확인했다고 보고하지 않는다.
5. 상품 수가 많으면 여러 배치로 나누어 진행한다. 배치마다 결과와 다음 작업 위치를 저장한다. 도구 한도나 접근 오류가 생기면 원인과 미완료 범위를 명시한다.
6. 로그인·성인 인증·CAPTCHA·접근 차단이 나타난 URL은 그 상태를 기록한다. 접근 가능한 다른 상품 수집은 계속 진행한다.

## 상품별 수집 항목

- 판매처 코드, 판매처 상품 ID, 정규화한 상품 상세 URL
- 원문 상품명, 페이지에 표시된 한국어 상품명
- 실제 제조사명, 작품명, 캐릭터명, 피규어 형태
- 스케일, 크기, 소재, 발매일 또는 입고 예정일
- JAN/EAN, 제조사 모델 코드, 에디션, 재판 여부
- 대표 이미지와 상세 이미지 URL, 이미지 출처 페이지
- 통화, 표시 판매가, 정가, 전액 결제 가격, 재고·예약 상태
- 예약금·잔금·회원가·쿠폰가·배송비·샵 특전·옵션 조건
- 확인 시각, 각 주요 판단의 출처 URL과 짧은 근거

페이지에 없는 값은 `null` 또는 `UNKNOWN`으로 남긴다. 캐릭터명·제조사·일정·가격을 추측해서 채우지 않는다. 옵션별 가격과 예약금·잔금을 전액 판매가와 구분한다. 가격이 모호하면 최저가 계산 대상에서 제외하고 이유를 저장한다.

## 기존 상품 대조와 중복 방지

1. JAN/EAN으로 기존 상품의 동일 버전을 찾는다. JAN이 같아도 세트 구성·스케일·에디션·재판 정보가 충돌하는지 확인한다.
2. JAN이 없으면 제조사 모델 코드와 제조사명, 원문·한국어 상품명, 캐릭터, 스케일, 버전, 이미지를 함께 대조한다.
3. 같은 캐릭터라는 이유만으로 동일 상품으로 연결하지 않는다. 예약·품절 표시, 판매처 접두어, 공백·기호 차이는 비교 시 정규화하되 버전·색상·세트 차이는 보존한다.
4. 기존 상품으로 확인되면 그 상품·버전에 판매처 가격을 연결한다. 동일 여부가 불명확하면 후보와 사유를 남기고 다른 상품 수집을 계속한다.
5. 네 판매처에서 발견한 동일 피규어는 하나의 상품으로 유지하고 판매처별 가격을 각각 연결한다.
6. 같은 상품 페이지를 다시 처리해도 상품·가격·이미지·출처가 중복 생성되지 않도록 한다. 상품 등록과 가격 연결은 같은 DB 트랜잭션에서 처리한다.

## 새 피규어의 ETC 등록

- 기존 목록에 없는 피규어로 확인되면 O_DOCK 상품 목록에 즉시 추가한다.
- 사용자 요청의 수집사 구분은 `ETC`다. 현재 데이터 모델에는 독립된 상품별 수집사 필드가 없으므로 먼저 실제 구조를 확인한다. 기존 모델을 이용하는 경우 `Manufacturer`의 `ETC` 그룹으로 등록하고 실제 제조사명은 별도의 출처 메타데이터에 보존한다. 이 매핑을 작업 결과에 명시한다.
- 새로 발견한 상품 때문에 기존 상품의 제조사 그룹을 ETC로 변경하지 않는다.
- 판매처 URL을 상품의 원본 출처로 보존한다. 제조사 공식 페이지로 확인한 정보와 판매처에서 확인한 정보를 구분해 기록한다.
- 한국어 상품명, JAN, 모델 코드, 이미지, 확인된 사양과 출처를 함께 저장한다. 판매처의 정가를 일본 제조사 공식 발매가로 저장하지 않는다.
- 아크릴 굿즈·키링·배송비·개인결제·잔금 결제 전용 항목을 피규어로 추가하지 않는다. 피규어인지 확인되지 않으면 이유와 함께 보류한다.
- 기존 번역·분류 큐가 있다면 새 상품을 등록한다. 현재 실행 중인 고정 배치에 새 상품이 자동 포함된다고 가정하지 말고 실제 큐 반영을 확인한다.
- 이미 수집된 `retailer_listings` 중 상품 카탈로그에 연결되지 않은 항목도 같은 기준으로 대조하고 신규 피규어 등록을 수행한다.

## 프로젝트 연결 지점

구현 전에 현재 코드를 읽고 실제 인터페이스를 확인한다.

- 상품·버전·이미지·출처 모델은 `backend/app/models/entities.py`에 있다.
- 판매처 listing/offer 모델은 `backend/app/models/retail.py`에 있다.
- 기존 가격 저장 로직은 `backend/app/services/retail_collection.py`의 `save_offer`다. 이 함수는 현재 가격 저장을 담당하며 신규 피규어 등록은 별도로 연결해야 한다.
- 판매처별 파서는 `backend/app/collectors/retailers/`에 있다. 파싱·정규화 로직은 재사용할 수 있다.
- 현재 `preview_domestic_prices.matches`는 JAN 후보를 제안하는 기능이다. 후보 제안만으로 기존 상품 연결 또는 신규 등록이 완료됐다고 판단하지 않는다.
- 번역·분류 대기열은 `backend/app/services/semantic_queue.py`를 확인한다.
- 국내 가격 비교는 `backend/app/services/domestic_prices.py`를 확인한다.
- 상품·가격 확인용 기존 API는 `/api/figures`, `/api/figures/{id}`, `/api/figures/{id}/prices`, `/api/retail-offers`, `/api/manufacturers`다. DB 반영에는 실제로 존재하는 쓰기 경로를 사용한다.

## 가격 표시 요구사항

- 상품 상세 상단에는 네 판매처 중 비교 가능한 가장 저렴한 전액 결제 가격을 표시한다.
- 그 아래 네 판매처를 모두 표시한다. 가격을 확보하지 못한 판매처는 `가격 없음`으로 표시한다.
- 동일 상품·버전으로 연결된 가격만 비교한다.
- 품절·오래된 가격·예약금·잔금·조건부 가격의 처리는 기존 비교 로직을 확인하고 정확하게 적용한다.
- 신규 ETC 상품도 상품 목록·상세 조회·국내 가격 비교에서 확인할 수 있어야 한다.

## 진행 기록과 검증

수집 결과는 `data/private/retail_price/chatgpt_direct/` 아래에 저장한다. 상품별 JSON에는 출처, 확인 시각, 대조 결과, 등록한 상품·버전 ID를 포함한다. 진행 파일에는 판매처별로 완료한 카테고리·목록 페이지·상품 URL, 다음 위치, 실패·보류 URL을 기록한다. 페이지 열람을 하지 않은 과거 자동 수집 결과는 과거 결과임을 표시한다.

첫 배치에서 기존 상품 가격 연결과 신규 ETC 피규어 등록을 실제 DB와 상품 API로 확인한 뒤 다음 배치를 진행한다. 신규 상품이 발견되지 않았다면 임의로 예시 데이터를 만들지 않는다. 재실행 시 중복이 발생하지 않는지 검증한다.

최종 보고에는 다음을 포함한다.

- ChatGPT가 직접 확인한 상세 페이지 수와 실제 저장한 가격 수
- 기존 상품에 연결한 수와 새로 추가한 ETC 피규어 수
- 중복으로 판정한 수, 피규어가 아니어서 제외한 수, 보류·실패 수
- 판매처별 완료·미완료 범위와 다음에 이어갈 위치
- 실제 추가한 상품 ID·이름·출처 URL 및 API 확인 결과

전체 탐색 범위의 처리가 확인된 경우에만 전체 완료라고 보고한다.
