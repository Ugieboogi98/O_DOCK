# 매니아하우스 POC 상태

후속 ‘확인하고 실행해’ 요청으로 2026-11-16 소량 dry-run을 구현·실행했다. 최신 실행 결과는 `07_POC_RUN_20261116.md`에 있다. 아래는 최초 정책 조사 시점의 기록이다.

2026-11-16 현재 `NOT_RUN_REQUIRES_PERMISSION`이다. 작업지시서 Phase C는 Phase B에서 허용 범위를 확인한 경우에 실행하도록 명시한다. 조사 결과가 `REQUIRES_PERMISSION`이므로 3~5개 상품 수집 POC는 실행하지 않았다.

## 검증 범위

| 지표 | 실제 결과 |
|---|---|
| 공개 접근 조사 | 매니아하우스 홈·목록 각 1개 HTTP 200 |
| 정책 조사 | robots·이용약관 각 1개 HTTP 200 |
| 상품 상세 본문 검증 | 0개, 홈 상품 링크 1개 열기에서 내용 확보 실패 |
| POC 추출 표본 | 0개 |
| 추출 성공률·가격 정확도·상태 정확도 | 분모 0, 측정 불가 |
| JAN 확보율·기존 상품 매칭률·오매칭 수 | 분모 0, 측정 불가 |
| 운영 DB 저장 | 0건 |

홈에 공개 표시된 블랑 포츈 익스프레스 상품은 예약·샵특전 문구가 있어 일반판과 구분할 필요가 있음을 확인했다. 홈에서 확인한 사실만 별도 JSON에 기록했으며, 상세 검증이나 파서 성공 표본으로 계산하지 않는다. [매니아하우스 홈](https://maniahouse.co.kr/)

## 허가 후 사용할 표본 절차

1. 허용된 목록 1페이지, 상세 최대 5개를 단일 동시 요청으로 확인한다.
2. 재고·예약·품절·할인·옵션·JAN 미노출 사례를 포함한다. 5개로 전 사례를 확보하지 못하면 미검증 항목을 남긴다.
3. 판매가와 정가를 라벨별로 비교하고 쿠폰·회원가·예약금·잔금·옵션 최저가를 조건부 가격으로 구분한다.
4. 통화·정수 KRW·표시 근거·판매 상태·상품 URL·시간을 확인하고 추정값은 NULL로 남긴다.
5. 원본 화면 사실과 파서 값을 사람이 대조해 표본별 판정표를 작성한다. JAN은 체크디지트와 제조사·판본까지 확인한다.
6. 같은 입력의 재처리는 같은 listing/offer를 갱신하는지 격리 DB에서 검사한다.
7. 403·429·CAPTCHA·로그인 요구를 관측하면 해당 출처 실행을 종료한다.

기본 실행 설계는 `enabled=false`, `dry_run=true`다. 현재 애플리케이션에 새 환경변수나 실행 경로를 연결하지 않았다. 수집·표시 허용 범위 확인 후 실제 POC와 지표 산출을 진행해야 한다.
