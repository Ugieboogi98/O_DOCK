## 1. 프로젝트 개요

### 1.1 한 줄 정의

**8개 피규어 제조사의 제품 데이터를 통합하고, 일본 공식 발매 엔가와 국내 신품·중고 판매 정보를 출처 기반으로 검색·비교하며, RAG 기반 AI가 제품 정보를 설명하는 웹서비스.**

### 1.2 목표

1. 8개 제조사의 피규어 관련 **전체 주요 제품군**을 장기 수집 대상으로 설정한다.
2. 제품 사양, 제조사, 작품/캐릭터, 시리즈, 제품번호, 발매 이력, 공식 자료를 정규화한다.
3. **발매 기준가는 일본 공식 발매 엔가(JPY)**로 안내한다. 일본 공식 엔가가 확인되지 않으면 미확인으로 표시한다. 핫토이 등 비일본 제조사는 일본 공식 발매 엔가가 없는 경우 원 발매 통화를 별도로 보여준다.
4. 국내 신품 가격은 **네이버 쇼핑의 검증 가능한 공식 판매 계정 및 지정 피규어샵을 포함한 공개 판매 페이지**를 검색해 제공한다.
5. 중고 가격은 **메루카리, 중고나라, 번개장터, 당근**의 수집 가능한 매물 정보를 사용해 별도 시세로 제공한다.
6. AI는 외부 검색을 도구로 호출하고 **동일 제품 여부를 검증**한다. 실제로 확인되지 않은 가격이나 출처를 생성하지 않는다.
7. 공식 상품 페이지 링크를 제공하고, **사용 권한이 확인된 제품 이미지**만 표시·저장한다.
8. PostgreSQL을 메인 DB로, Vue 3를 웹 프론트엔드로, FastAPI를 백엔드로 사용한다.
9. 과제 명세의 RAG 필수 기능(F2001~F2012)을 모두 구현하고, Vue를 통한 F2013 심화 기능을 추진한다.

### 1.3 확정 기술 스택

| 영역 | 기술 | 담당 역할 |
|---|---|---|
| Frontend | **Vue 3 + Vite** | 웹 화면, 제품 도감, 비교, 채팅 |
| Styling | Tailwind CSS | 반응형 디자인 |
| Backend | **FastAPI** | REST API, 검색 조율, RAG 서비스 |
| RDBMS | **PostgreSQL** | 제품 마스터·가격 이력·판매처·수집 기록 |
| ORM / Migration | SQLAlchemy 2.x / Alembic | DB 접근, 스키마 버전 관리 |
| Vector DB | **ChromaDB** | 메타데이터와 외부 문서 2개 컬렉션 |
| RAG | LangChain + LangGraph | 검색(retrieve) → 생성(generate) |
| LLM | 프로젝트에서 사용 가능한 모델/API | 검색어 생성, 문서 후보 선별, 답변 작성 |
| 웹 검색 | 이용 가능한 웹 검색 API·허용된 판매처 연동 | 상품 페이지 발견 |
| 수집기 | Python, Requests, BeautifulSoup | 허용된 정적 페이지 수집 |
| 동적 페이지 | Playwright (필요·허용 시) | JS 렌더링 페이지 처리 |
| 검증 | pytest | 데이터·API·RAG·가격 매칭 테스트 |
| 실행·배포 | Docker Compose | 서비스별 개발 환경 구성 |

> **구분:** SQLite/Streamlit은 기존 검토안이었으며 **최종안에서는 사용하지 않는다.** `pgvector`는 향후 통합 가능성만 검토하고, 이번 과제의 RAG 2컬렉션은 **ChromaDB**로 유지한다.

- 네이버의 과거 쇼핑 검색 Open API에 의존하지 않는다. 새 검색 API/제휴 방식의 사용 가능성 및 이용 조건을 확인하고, 검색 API에서 노출된 공개 상품 페이지를 통해 탐색한다.
- 검색 API의 상품 누락, 검색 시점 차이, 가격 노출 제한 때문에 **전체 판매처의 실시간 최저가를 보장할 수 없다.**

### 2.4 접근성·법적 검증 상태

> 공식 사이트의 제품 페이지가 공개되어 있어도 **대량 크롤링 및 이미지 재사용 허가가 자동으로 생기는 것은 아니다.** 다음은 구현 전 검증 절차이며, 승인 완료 여부를 뜻하지 않는다.

- `robots.txt`, 이용약관, 저작권·이미지 사용 규칙, 요청 빈도 제한 확인
- 공개 API·상품 피드·사이트맵·제휴 채널 확인
- 정적 HTML vs JavaScript 렌더링 및 페이징 구조 확인
- 10~20개 단위 **소량 수집 테스트**로 필드 추출·정합성 평가
- 허용된 경로에만 요청하고 요청 간격·재시도·식별 정보(User-Agent) 준수
- 로그인이 필요한 비공개 데이터, 접근 제어 또는 차단을 우회하는 방식은 사용하지 않음
- 각 가격·이미지·상품 설명에 원본 URL, 접근 시각, 이용 조건 상태 기록

## 3. 가격 정책 (최종)

### 3.1 발매 정가의 정의

- 메인 '발매가'에는 **제조사가 공개한 일본 공식 발매 엔가(JPY)**를 사용한다.
- 확인된 발매 엔가의 **금액, 통화, 세금 포함 여부, 제품 버전, 출처 URL, 발표/확인 날짜**를 보존한다.
- 일본 공식 발매 엔가가 없으면 **`발매 엔가 미확인`**으로 표시한다.
- 핫토이처럼 원 발매 통화가 JPY가 아닌 경우 원 발매 통화 가격을 별도 제시할 수 있으나, **환산 엔가를 공식 발매 정가로 가장하지 않는다.**
- 재판·별도 버전에 공식 정가가 달라졌으면 해당 버전의 발매가로 관리한다.

### 3.2 국내 신품 가격

- 네이버 쇼핑 공식 계정 및 지정 국내 쇼핑몰 등의 **검색 결과에서 실제로 확인한 가격**을 제공한다.
- 저장 항목: 판매처명, 제품 URL, 판매 상태, 정상 판매가, 할인가, 예약가, 배송비(확인 가능 시), 확인 시각.
- 공식성 증명이 없는 국내 쇼핑몰 가격을 `공식 한국 정가`로 표시하지 않는다.
- 동일한 제품이고 구매 가능한 상태인 **신품 최저 표시 가격**을 산출할 수 있다. 배송비 포함 기준인지는 반드시 표기한다.
- 각 쇼핑몰의 개별 가격도 목록으로 제시한다.
- 사용자에게 **'새 가격 검색'** 동작을 제공하고, 마지막 검색 시각과 캐시 데이터를 표시한다.

### 3.3 중고 가격

- 중고 시세는 발매가·신품 판매가와 **독립된 구역**에 표시한다.
- 한국 플랫폼은 KRW, 메루카리는 JPY로 원 통화를 유지한다.
- 별도 환산 원화가 필요한 경우 환율 기준 시각과 함께 참고치로만 제공한다.
- 국제 배송, 구매대행 수수료, 세금은 확인되지 않으면 합산하지 않는다.
- 판매 중 매물의 중앙값과 완료 표시 매물의 가격 통계는 분리한다.

### 3.4 화면 표시 예시 (가상 수치)

| 가격 구분 | 예시 표시 | 데이터 근거 |
|---|---|---|
| 일본 공식 발매가 | ¥12,800 | 일본 공식 상품 상세 |
| 국내 신품 최저 확인가 | ₩145,000 | 국내 판매처 상품 페이지 |
| 국내 판매처별 가격 | A몰 ₩145,000 / B몰 ₩159,000 | 해당 상품 URL |
| 국내 중고 매물 중앙값 | ₩110,000 (7건) | 동일 제품·상태 매물 |
| 메루카리 매물 중앙값 | ¥8,000 (5건) | 동일 제품 매물 |

> 위 숫자는 **데이터 구조를 설명하기 위한 가상 사례이며 실제 판매 정보가 아니다.**

## 4. AI 검색 에이전트 설계

### 4.1 원칙

**AI는 검색을 수행할 도구를 호출하고 결과를 구조화하는 역할**이다. LLM에게 가격을 추측하게 하지 않는다.

```text
[사용자가 피규어 선택]
       ↓
[PostgreSQL에서 제품 고유정보 조회]
  (제조사, 작품, 캐릭터, 제품번호, 버전, 일본어명)
       ↓
[LLM 검색어 생성 (한국어/일본어/영어)]
       ↓
[검색 API / 허용된 판매처 API·수집기]
       ↓
[후보 상품 URL + 가격·상태 추출]
       ↓
[제품 일치 검증: ID/SKU/제조사/버전/스케일]
       ↓
[중복 제거·통화 정규화·상태 필터·가격 계산]
       ↓
[PostgreSQL에 가격 관측 이력 저장]
       ↓
[Vue: 가격 + 판매처 + 원문 링크 + 확인 시각]
```

### 4.2 제품 매칭 규칙

**우선 규칙:** 제조사 SKU/JAN/제품번호 등 안정적인 식별자가 일치할 때 높은 신뢰도를 부여한다.

보조 비교 속성:

- 제조사 / 브랜드·제품군
- 작품명 / 캐릭터명 (한국어·일본어·영어 동의어)
- 스케일 / 크기 / 색상 / 재판 여부
- 한정판, 특전판, 세트 제품 여부

명확하지 않으면 `MATCH_REVIEW_REQUIRED`로 두고 자동 가격 집계에서 제외한다. 같은 캐릭터의 다른 제품을 한 시세로 섞지 않는다.

### 4.3 검색 및 캐시 정책

- 평상시: **DB 저장 가격**과 최종 확인 시각 즉시 출력
- 사용자 새로고침: **검색 API 재호출 → 후보 검증 → 새 가격 관측 저장**
- 중복 검색 최소화를 위한 캐시 및 요청 제한
- 가격을 확인할 수 없으면 `미확인`, 상품 페이지 접속 실패는 `조회 실패`로 구분
- 검색 결과에 링크만 있고 가격은 없다면 **링크만 표시**하고 금액을 만들어내지 않음

### 5.2 데이터 품질·무결성

- `manufacturers` → `figures` → `figure_variants` 관계로 제품 식별

- 외부 데이터 수집 원문(JSON/HTML 등)은 허용된 범위에서 보존하여 추출 오류 검증 가능하게 함

## 6. ChromaDB와 RAG 파이프라인

과제 명세의 **메타데이터 색인(RAG 1)**과 **외부 문서 색인(RAG 2)**을 구분한다.

| 컬렉션 | 내용 | 필수 메타데이터 |
|---|---|---|
| `figure_metadata` | 제품 1건의 검색용 메타데이터 텍스트 | figure_id, variant_id, manufacturer, title, source_type |
| `figure_documents` | 공식 제품 설명·외부 문서 청크 | figure_id, variant_id, doc_id, title, source_url, source_type, collected_at |

### 6.1 필수 프롬프트 3개

1. **검색어 추출(프롬프트 1):** 선택한 제품 + 사용자 질문에서 외부 자료 탐색용 검색어 추출, 파싱 가능한 형식(JSON 등).
2. **후보 선별(프롬프트 2):** 검색된 문서의 제목·요약을 보고 관련 문서 선별. **선택한 제품 자체를 설명하는 공식 문서는 제외하지 않음.**
3. **답변 생성(프롬프트 3):** 검색된 문서만 근거로 답하고, 인용 번호와 함께 주요 주장을 제시. 근거 없으면 `문서에서 확인되지 않음`으로 응답.

### 6.2 필수 동작

- 제품 메타데이터는 검색 결과에 **항상 포함**.
- 외부 문서 청크는 제품 ID 등으로 필터링 후 의미 유사도 검색.
- 두 컬렉션 결과 병합 및 중복 제거, `Top-k` 설정 가능.
- LangGraph의 최소 `retrieve`, `generate` 두 노드 구현.
- 답변에 **실제로 인용한 근거 문서의 제목과 원문 URL**만 표시.
- 인용 근거가 없으면 근거 없음 안내.
- 청크 크기·중복 길이는 설정으로 변경: 시작 예시 `chunk_size=1000`, `chunk_overlap=200` (명세서의 예시, 확정값 아님).
- 컬렉션 재색인 시 동일 제품 중복 증가 방지: 안정적인 청크 ID 사용.

### 6.3 AI가 처리하는 질문 예시

- “이 제품의 공식 높이와 재질은 무엇인가?”
- “같은 캐릭터의 메가하우스 제품과 코토부키야 제품의 차이점은?”
- “1/7 스케일이며 2025년에 나온 제품을 찾아줘.”
- “이 피규어의 일본 발매가와 현재 국내 최저 확인가는?”
- “현재 조회 가능한 미개봉 중고 매물의 중앙값은?”

> 수치 조건(가격·높이·발매일)은 **PostgreSQL 정확 필터**, 의미 검색 및 공식 문서 설명은 **ChromaDB RAG**, 실시간 시세 탐색은 **별도의 검색 도구**로 처리한다.

## 11. 작업 일정 및 우선순위

### 11.1 과제 3일 MVP (필수 요구사항 우선)

| 시점 | 목표 | 완료 조건 |
|---|---|---|
| **1일 차** | 도메인 확정, 사이트 접근성 확인, PostgreSQL 스키마, 제품 100건 이상 확보, 메타데이터 색인 | 1일 차 16시까지 도메인 조건 입증, F2001~F2002 |
| **2일 차** | 외부 문서 수집·청킹·2컬렉션 RAG, LangGraph, FastAPI 및 기본 Vue UI | F2003~F2009의 핵심 흐름 동작 |
| **3일 차** | 자연어 조건 검색·제품 비교·상태 안내·테스트·문서화 | F2010~F2012 검증, 가능하면 F2013 구현 |

> **리스크:** Vue + FastAPI + PostgreSQL + 8개 사이트 수집 + 가격 검색 + RAG를 모두 3일 안에 완성하는 것은 고위험이다. 과제 기간에는 **RAG 필수 기능과 제출 검증을 먼저 완료**하고, 국내/중고 가격 검색의 폭넓은 연동은 확장 단계로 나눈다.

### 11.2 확장 단계

1. 8개 제조사 수집기 순차 확대, 800건 이상 목표
2. 네이버 및 국내 피규어샵 가격 검색 에이전트 추가
3. 4개 중고 플랫폼 가격 연동(허용된 방법 기준)
4. 가격 변동 이력, 중고 상태별 시세 통계 및 대시보드
5. MMR, 다중 문서 출처, RAG 품질 비교 보고서
6. 성능 최적화·접근성·UI 개선 및 배포

## 12. 검증 기준

| 항목 | 테스트 방법 |
|---|---|
| 제품 수집 | 제조사별 수집 성공 건수·필수 필드 보유율 확인 |
| 중복 방지 | 동일 색인 스크립트 2회 실행 후 청크 수 변화 없는지 확인 |
| 제품 일치 | 동일 캐릭터의 다른 제조사·버전·재판이 섞이지 않는지 확인 |
| 가격 정확도 | 화면 가격과 해당 판매처 원문 가격·통화·확인 시각 비교 |
| 중고 가격 | 상품 상태·판매 상태·세트 상품 분리 및 표본 수 표시 |
| RAG 검색 | 청크 크기, overlap, Top-k 설정 변경에 따른 결과 비교 |
| RAG 답변 | 문서에 없는 질문에서 추측하지 않는지 확인 |
| 인용 | 본문 인용 번호와 화면 실제 출처 목록 일치 |
| UI | 제품별 대화 기록 분리, 검색 필터, 진행/오류 안내 |
| 수집 정책 | 출처별 수집 가능 범위·이미지 사용 조건 증빙 |
| 보안 | `.env` 비공개, 서버 스택 추적 및 API 키 노출 없음 |

**권장 자체 품질 목표(명세서 수치 기준 아님):** 제품명·제조사·출처 식별 100%, 중복 고유 제품 0건, 핵심 필수 기능 전체 통과. 나머지 완전성·최신성은 실제 사이트 접근 가능성에 따라 측정한다.

## 14. 구현 전 미해결 사항 및 결론

### 반드시 검증해야 할 사항

1. 8개 제조사별 **대량 자동 수집 허용 여부**와 공식 데이터 API 존재 여부
2. 네이버 공식 판매 계정의 **검증 기준**과 검색 API/제휴 접근 가능 여부
3. 4개 중고 플랫폼의 **검색 API/이용 조건**과 실거래 정보 접근 여부
4. 공식 제품 이미지의 **저장·재배포·핫링크 허용 범위**
5. 제조사별 제품 식별자(SKU/JAN)의 품질과 버전·재판 처리 규칙
6. 실시간 가격 탐색의 검색 비용, 호출 속도, 가격의 최신성 안내
7. 한국어·일본어 제품명 동의어 사전 및 정확한 상품 매칭 테스트

### 최종 개발 방침

**Vue 3 → FastAPI → PostgreSQL + ChromaDB**를 핵심 구조로 사용한다. 피규어 제조사 공식 정보는 정형 데이터와 출처 문서로 저장하고, **발매 기준가는 공식 일본 엔가**, **국내 가격은 AI 도구 기반 판매처 검색**, **중고 가격은 상태별 매물 시세**로 분리한다. 사용자에게는 제품 이미지(권한 확보 시), 공식·판매 링크, 가격 확인 시각, AI 답변 근거를 함께 제공한다.

**우선순위는 `과제 필수 RAG 완성 → 8개 제조사 수집 확장 → 신품 AI 가격 검색 → 중고 시세 연동`이다.**
