# O_DOCK UI/UX 리팩터링 결과 · 2026-11-17

## 적용 결과

최신 요청에 따라 화이트·스카이블루 기반의 공통 디자인을 기존 `http://localhost:8080` 프론트엔드에 반영했다. 실제 상품 사진을 시각적 중심으로 두고 제조사 탐색은 선으로 구분한 목록으로 정리했다. 검색·필터·정렬·관심상품·구매·가격 계산 API와 저장 로직을 유지한다.

Unslop by [Damir Sokolovsky](https://github.com/heydamir/unslop), CC BY 4.0. 설치 경로는 `docs/design/skills/unslop`이다. 공식 설치 도우미를 사용해 프로젝트의 쓰기 가능한 문서 경로에 설치했으며, 현재 세션에서는 문서를 읽어 규칙을 적용했다.

| 행사 | 별도 파란색, 회전 장식, 작은 날짜 | 공통 표면, 의미 있는 일정 상태색, 메타 확대 |

사진 배경은 상품의 원래 흰 촬영 배경과 어울리는 밝은 중립색을 사용한다. 상품명과 콘텐츠는 바꾸지 않았다. 장식용 PRODUCT VIEW 표시는 제거했다.

## 변경 파일

프론트엔드:
- `src/main.js`: 최종 디자인 시스템 스타일 연결.
- `src/design-system.css`: 색상·글꼴·간격·상태·반응형 규칙.
- `src/style.css`, `src/home-design.css`, `src/white-theme.css`, `src/events.css`: 기존 레이아웃 유지, 하드코딩 색상 토큰화, 이미지 혼합·과도한 글꼴 무게 정리. white-theme.css는 기존 상세 레이아웃을 보존하기 위해 파일명을 유지했다.
- `src/App.vue`: 브랜드, 모바일 메뉴, 본문 건너뛰기.
- `src/views/HomeView.vue`: 실제 서비스에 맞는 안내 문구와 제조사 제목.
- `src/components/FigureCard.vue`: 이미지 오류 상태, 기존 비교·관심 액션 유지.
- `src/components/ComparisonPanel.vue`: 키보드 접근성.
- `src/components/DomesticPrices.vue`: 토큰 기반 가격 표.
- `src/views/FigureDetailView.vue`, `src/views/KoreanSearchView.vue`: 스타일 토큰화 및 사진 장식 문구 정리.

문서·검증:
- 이 보고서, `unslop-audit.md`, `design-system.md`.
- `before-checks.json`, `after-checks.json`, `interaction-checks.json`.
- `screenshots/before-*`, `screenshots/after-*`: 홈·목록·상세·행사·계정의 375px / 1440px 전후 이미지.
- `tools/design-check/capture.cjs`, `interactions.cjs`: 독립 Playwright 검증 스크립트. Playwright는 이 도구 디렉터리에만 설치했다. 프론트엔드 package.json과 lockfile에 UI 의존성을 추가하지 않았다.

## 검증

- Vite 프로덕션 빌드 성공. Docker 프론트엔드 재빌드·재시작 완료.
- 기존 Vitest 8개 파일 / 38개 검사 통과.
- 실제 14개 라우트를 375 / 430 / 768 / 1280 / 1440 / 1920px에서 점검. 1차 84개 조건에서 가로 넘침과 pageerror 0건. 최종 결과는 `after-checks.json` 참조.
- 화면 대상: 홈, 전체 상품, 상품 상세, 행사, 검색, 관심상품, 로그인, 구매 목록, 제조사, 작품, 신상품, 가격 비교, AI 채팅, 데이터 현황.
- 모바일 메뉴 펼침과 이동, 제조사 필터의 URL 반영, 필터 초기화, 다음 페이지 이동, 비교창 열기 및 Escape 닫기, 상세 가격표 4행과 외부 출처 링크, 헤더 검색 경로, 로그인 필드 표시 확인.
- 비교와 한국어 검색 POST 응답은 테스트에서 대체했다. GET 조회는 실제 서비스에 연결했다. 브라우저의 나머지 쓰기 요청을 차단해 계정·관심상품·구매 데이터에 테스트 기록을 만들지 않았다.
- 주요 색상 대비: 본문/배경 17.45:1, 보조/부각 표면 7.29:1, 오렌지/표면 6.21:1, 버튼 글씨/오렌지 6.79:1. 모두 일반 텍스트 AA 기준 4.5:1 이상.
- API services, stores, router 계약, DB 스키마·데이터, 백엔드, 수집·번역·RAG, 환경변수 및 Docker 볼륨은 이번 리팩터링에서 수정하지 않았다.

## 범위와 남은 검증

전체 WCAG 2.2 AA 인증 결과는 아니다. 스크린리더 실제 사용, 모든 콘텐츠 이미지 대비, 인증 후 실제 관심상품·구매·계정 쓰기 동작, 검색 모델의 답변 품질은 이번 브라우저 검사로 검증하지 않았다. 기존 단위 검사와 비즈니스 로직 유지로 회귀 위험을 줄였다. 데이터에 없는 이미지·가격·번역은 기존 미확인 상태로 표시한다.

브라우저 연결 호스트를 사용할 수 없어 독립 Chromium으로 화면을 캡처했다. Windows 제한 환경에서 esbuild의 경로 접근이 거절된 첫 빌드 시도는 일반 실행 권한으로 재실행해 통과했다.

## 화이트·스카이블루 변경 검증

최신 요청의 색상 방향을 우선 적용했다. 레이아웃과 기능은 유지하고 오류·행사 상태색도 밝은 화면에 맞게 조정했다. Docker 프로덕션 빌드와 배포, 주요 상호작용 8개가 통과했다. 최신 대비는 본문 14.55:1, 보조 글씨 5.28:1, 포인트 글씨 5.81:1, 버튼 글씨 7.81:1이다.

14개 화면을 데스크톱·모바일에서 확인한 28개 조건 모두 가로 넘침과 JavaScript 실행 오류가 없었다. 최신 화면은 `screenshots/white-*`, 결과는 `white-checks.json`이다. 이전 `after-*`와 최초 대비 수치는 다크 디자인 이력이다.
